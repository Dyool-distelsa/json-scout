# JSON Scout v0.2.4

These are preparation notes for the next combined Windows/Linux stable release. The `v0.2.4` metadata and notes are prepared, but this change does not publish the release. The current remote verification snapshot is recorded below; its draft assets are not published stable-download availability.

## Highlights

### Azure Key Vault diagnostics

The secret-safe diagnostic work carried forward from the unpublished v0.2.3 draft remains available:

- View the latest diagnostic after a transient error toast expires.
- Copy a redacted diagnostic report, or use its displayed fallback when clipboard access is unavailable.
- Keep reports in session memory only; they are not written to disk or published automatically.
- Keep secret values, raw CLI output, staged paths and credentials out of diagnostics.

### Windows Azure CLI UTF-8 handling

- Validated isolated Azure CLI ZIP runtimes, including the known Scoop `current` layout, are invoked through their paired bundled Python with explicit UTF-8 settings (`-X utf8 -I -B -m azure.cli`). This avoids the console-code-page output observed with accented JSON from the bundled Python runtime.
- Azure CLI stdout remains strict UTF-8: invalid bytes are rejected rather than lossily rewritten, protecting secret values from silent corruption.
- Unsupported layouts retain the existing `az.cmd` compatibility fallback when available. That fallback is not guaranteed to repair every installation, and the change does not parse arbitrary PATH scripts.

## Platform status

- **Stable:** Windows and Linux. Their existing release workflow and signing limitations are unchanged.
- **Experimental only:** macOS has a separate manual, ad-hoc-signed workflow. These notes make no macOS support claim; see [the macOS v0.2.4 experimental notes](macos-v0.2.4.md).
